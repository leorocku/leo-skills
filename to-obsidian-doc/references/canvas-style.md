# Canvas 样式：明暗主题都要清楚

目标只有一个：同一张 `.canvas`，用户切到 light 主题看得清，切到 dark 主题也看得清，不需要手动调。

## 为什么十六进制颜色不能用

Obsidian 渲染 canvas 节点时，颜色最终落到 CSS 变量 `--canvas-color`（一个 `R, G, B` 三元组）上，节点背景是它的低透明度版本，边框是它的高透明度版本。

- **预设色 `"1"`–`"6"`** 是通过 `.mod-canvas-color-N` 类设置的，Obsidian 在亮色和暗色主题下各定义了一套值。**它自己会变**，所以天然两边都合适。
- **十六进制色** 由 Obsidian 直接换算成 RGB 写进 `--canvas-color`，**两个主题下都是同一个值**。于是：深色 `#1A1A2E` 在白底上还行，到了暗色主题就和背景糊在一起；浅色 `#FFEE88` 反过来。

这就是"在 light 下好看，切到 dark 就瞎了"的根因。**所以默认只用预设色。**

## 颜色规则

**用预设**（首选，永远安全）：

| 预设 | 观感 | 适合表达 |
|---|---|---|
| `"1"` | 红 | 问题、风险、阻塞 |
| `"2"` | 橙 | 待办、注意 |
| `"3"` | 黄 | 补充说明 |
| `"4"` | 绿 | 结论、可行方案 |
| `"5"` | 青 | 数据、事实 |
| `"6"` | 紫 | 概念、定义 |

**不设 `color` 也可以**，节点会用主题的默认灰。大多数节点其实不需要颜色，颜色一多反而看不出重点。只在需要区分类别时才上色，一张图里最多用 2–3 种。

## 文字：不要设颜色，不要加描边

**不要给文字设任何颜色**，也不要加 `-webkit-text-stroke`、`text-shadow` 之类的描边或阴影。原因很直接：文字颜色一旦写死，就只在某一个主题下看得清；而 canvas 里的文字**继承主题自己的前景色**（`--text-normal`）时，在任何主题下都是对比度最好的状态。描边是为了补救"文字颜色写死了导致看不清"，而只要不写死，就根本不需要补救。

同样不要用颜色去"强调"文字——需要强调就用加粗或标题层级，那是主题无关的。

**描边只加在图形边框上，不加在文字上。** 这是本文的核心约定。

## 需要明确描边时：中灰中间调

预设色给的是"淡色填充 + 同色边框"，够用且安全。但如果要的是**只有边框、没有填充**的高对比度轮廓（比如把一组节点框成一个整体、画一个强调框），用中灰这一档颜色，它同时远离白底和深底，两边都够看：

| 用途 | 十六进制 | 在白底(#FFFFFF) | 在深底(#1E1E1E) |
|---|---|---|---|
| 中性描边（最稳） | `#7A7A7A` | 约 4.3:1 | 约 3.9:1 |
| 蓝色描边 | `#4A80B0` | 约 4.2:1 | 约 4.0:1 |
| 绿色描边 | `#5E9E5E` | 约 3.4:1 | 约 4.9:1 |
| 橙色描边 | `#C08A3E` | 约 3.1:1 | 约 5.4:1 |

两侧都超过 WCAG 对非文字图形要求的 3:1。`#7A7A7A` 是最保险的一档——它是"中间调"，无论主题往哪边偏都不会失效。

**要避开的**：`#000000`、`#FFFFFF`、以及任何亮度低于 20% 或高于 80% 的颜色。它们必然在某一侧消失。

显式描边用内联 HTML 写在文本节点里（Obsidian 会照常渲染 Markdown 里的行内 HTML）：

```html
<div style="border:2px solid #7A7A7A; border-radius:8px; padding:10px;">

这里是节点内容，正常写 Markdown。

</div>
```

关键点：**不设 `background`**，让它保持透明，这样底色始终由主题决定。一旦写了 `background:#fff`，暗色主题下就成了白板。

边框粗细用 `2px` 起步；`1px` 在暗色主题下会因为抗锯齿显得发虚。

## 分组用 group 节点

要把几个节点归成一类，用 `group` 节点而不是画一个巨大的 HTML 框。group 自带标题栏和边框，且边框同样跟随主题：

```json
{
  "id": "d4e5f6789012345a",
  "type": "group",
  "x": -50, "y": -50, "width": 1000, "height": 600,
  "label": "网络模式"
}
```

子节点的坐标要落在 group 的范围里，四周留 40px 左右内边距。group 的 `color` 也用预设，或者不设。

## 连线

边的 `color` **不设**，跟随主题默认值。非要区分时才用预设 `"1"`–`"6"`。边的 `label` 保持简短，一两个词就够。

## 完整例子

一个关于 Docker 网络模式的图，全部遵守上面的规则——只用预设色，文字无颜色无描边，唯一的显式描边是中灰边框：

```json
{
  "nodes": [
    {
      "id": "a1b2c3d4e5f60718",
      "type": "text",
      "x": 0, "y": 0, "width": 320, "height": 100,
      "text": "# Docker 网络模式\n\n三种模式，按隔离程度分。"
    },
    {
      "id": "b2c3d4e5f6071829",
      "type": "group",
      "x": -40, "y": 180, "width": 1120, "height": 260,
      "label": "常用模式"
    },
    {
      "id": "c3d4e5f607182930",
      "type": "text",
      "x": 0, "y": 240, "width": 320, "height": 160,
      "text": "## bridge\n\n默认模式。\n容器靠 IP 通信。\n\n色标：绿"
    },
    {
      "id": "d4e5f60718293041",
      "type": "text",
      "x": 360, "y": 240, "width": 320, "height": 160,
      "text": "## host\n\n共用宿主机网络。\n没有隔离。\n\n色标：橙",
      "color": "2"
    },
    {
      "id": "e5f6071829304152",
      "type": "text",
      "x": 720, "y": 240, "width": 320, "height": 160,
      "text": "<div style=\"border:2px solid #7A7A7A; border-radius:8px; padding:10px;\">\n\n**none**\n\n只有 lo 回环。\n完全隔离。\n\n</div>"
    }
  ],
  "edges": [
    {
      "id": "f607182930415263",
      "fromNode": "a1b2c3d4e5f60718", "fromSide": "bottom",
      "toNode": "b2c3d4e5f6071829", "toSide": "top",
      "toEnd": "arrow"
    },
    {
      "id": "0718293041526374",
      "fromNode": "c3d4e5f607182930", "fromSide": "right",
      "toNode": "d4e5f60718293041", "toSide": "left",
      "label": "对比"
    },
    {
      "id": "1829304152637485",
      "fromNode": "d4e5f60718293041", "fromSide": "right",
      "toNode": "e5f6071829304152", "toSide": "left",
      "label": "隔离更强"
    }
  ]
}
```

注意第三个节点：JSON 字符串里内联 HTML 的引号必须转义成 `\"`。

上面这份 JSON 是**文件最终应该长什么样**。但真正写进 vault 时要经过 `content=`，而它会把 \n 变成真正的换行——JSON 字符串里不允许出现裸换行，文件就坏了。

## 怎么把它写进 vault

`obsidian create` 的 `content=` 会做转义处理，实测结果：

| 你写的 | 文件里实际得到 | 结果 |
|---|---|---|
| `\n` | 真正的换行 | **JSON 坏了** |
| `\\n` | 仍然是换行（反斜杠被吃掉） | **JSON 也坏了** |
| `\u000A` | 原样保留，解析时还原成换行 | **正确** |

所以交付时，把 JSON 里每一个 \n 都替换成 \u000A，再通过 `content=` 传给 `obsidian create`。

**写完必须读回来再解析一次。** 用 \n 写进去时，`create` 照样回 `Created:`、退出码是 0，但 `json.load` 会报 `Invalid control character at ...`，文件在 Obsidian 里根本打不开。这是典型的「看起来成功了的失败」，不验证就发现不了。

## 布局

- 坐标可以是负数，画布无限大。`x` 向右增，`y` 向下增，坐标是**左上角**。
- 节点之间留 50–100px 间距，别贴在一起。
- 坐标取 10 或 20 的整数倍，排出来才齐。
- 常用尺寸：小节点 300×120，中节点 360×180，大节点 480×300。

## 生成后检查

1. JSON 能解析（最容易坏在文本里的引号和换行）
2. 所有 `id` 唯一，且是 16 位十六进制
3. 每条边的 `fromNode` / `toNode` 都能对上真实节点
4. 每个节点都有 `id`、`type`、`x`、`y`、`width`、`height`
5. `color` 只出现 `"1"`–`"6"` 或上面表格里的中灰档，**没有纯黑纯白、没有深色或浅色的十六进制**
6. 文本里没有 `color`、`-webkit-text-stroke`、`text-shadow`
7. 显式描边的 div 没有设 `background`
